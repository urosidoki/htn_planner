# HTN validation

`.github/workflows/htn-validation.yml` runs on push/pull requests to main and
manual dispatch. The uploaded source did not contain the existing repository
workflow; this is an independent file, not a replacement for an unseen workflow.
If the repository already performs the same builds, merge the matrices there or
disable the duplicate after the new workflow passes. No repository settings,
required checks, or remote workflows have been changed by this patch.

## Windows x64 matrix

| Variant | Configuration | Extra options | Tests |
| --- | --- | --- | --- |
| debug | Debug | none | Full suite |
| profile | Profile | none | Full suite |
| release | Release | none | Full suite |
| detailed-diagnostics | ProfileDetailed | atom diagnostics, coarse profiling, runtime backtracking enabled | Full suite |
| profile-coarse-diagnostics | Profile | atom diagnostics, coarse profiling, runtime backtracking enabled | Full suite |
| profile-timing-only | Profile | benchmark allocation probe disabled | Full suite |

A separate `generated-frontend-boundary` job builds `HTNSDK.sln` with
`--sdk`, verifies that nodes and the legacy domain frontend are absent from the
framework project, then runs `--check` and
translation for `AAACombatNPC` with that isolated translator.

Each job checks out a fresh tree, generates the VS2022 solution with its own
options, restores GoogleTest, and rebuilds the whole generated solution (including
demo/editor/tools and both compatible/incompatible module fixtures). Domain sources
are regenerated by the matching translator during prebuild. Do not reuse a
translator or generated domains emitted under a different configuration: generated
profiling storage/lifecycle can depend on the translator's compilation flags.

Tests run from the repository root so fixture paths resolve. They exercise the public
planning-unit path, missing-definition rejection, recovery after no-plan, per-entity
isolation and module lifecycle/ABI rejection. A report with zero tests is rejected.

The allocation self-test runs when the probe is enabled. Non-Debug jobs also run
100-plan lifecycle smoke tests; expensive FactHeavy100 is excluded.
Benchmark failure exit codes fail CI, but wall-clock timings have no pass/fail
threshold on shared runners. Tests XML, lifecycle text and MSBuild binary logs are
saved for seven days even if later steps fail. Matrix jobs do not fail fast.

The workflow uses read-only repository permissions and no persisted checkout
credentials. No secrets or publishing permissions are required. Action usage follows
the maintainers' documentation for [checkout](https://github.com/actions/checkout),
[MSBuild setup](https://github.com/microsoft/setup-msbuild),
[NuGet setup](https://github.com/NuGet/setup-nuget), and
[artifact upload](https://github.com/actions/upload-artifact).

## Representative local Profile verification

Run these PowerShell commands from the repository root on Windows:

```powershell
& .\ThirdParty\premake\bin\premake5.exe vs2022
if ($LASTEXITCODE) { throw 'Generation failed' }
nuget restore HTN.sln -NonInteractive
if ($LASTEXITCODE) { throw 'Restore failed' }
msbuild HTN.sln /m /t:Rebuild /p:Configuration=Profile /p:Platform=x64
if ($LASTEXITCODE) { throw 'Build failed' }
& .\bin\Profile-windows-x86_64\HTNTest\HTNTest.exe
if ($LASTEXITCODE) { throw 'Tests failed' }
& .\bin\Profile-windows-x86_64\HTNBenchmark\HTNBenchmark.exe --allocation-self-test
if ($LASTEXITCODE) { throw 'Self-test failed' }
& .\bin\Profile-windows-x86_64\HTNBenchmark\HTNBenchmark.exe 20000 1 --lifecycle
if ($LASTEXITCODE) { throw 'Lifecycle failed' }
```

For representative timing without a replacement-new probe:

```powershell
& .\ThirdParty\premake\bin\premake5.exe --no-benchmark-allocations vs2022
if ($LASTEXITCODE) { throw 'Generation failed' }
msbuild HTN.sln /m /t:Rebuild /p:Configuration=Profile /p:Platform=x64
if ($LASTEXITCODE) { throw 'Build failed' }
1..3 | ForEach-Object {
    & .\bin\Profile-windows-x86_64\HTNBenchmark\HTNBenchmark.exe 20000 1 --lifecycle |
        Tee-Object -FilePath "profile-timing-$_.txt"
    if ($LASTEXITCODE) { throw 'Lifecycle failed' }
}
```

Allocation columns must be n/a in that build; do not run the allocation self-test
there (it intentionally exits nonzero when disabled). Compare repeated warmed
timing samples on the same quiet machine, not diagnostic-build timings or single
setup/first samples. Regenerate without --no-benchmark-allocations and rebuild to
restore the probe afterward.

## Validation boundary

Workflow execution, MSVC/full GoogleTest and whole GUI-solution builds must be
confirmed on Windows/GitHub Actions. Local Linux checks are not substitutes for
those results. The premake workflow is Windows-only; it does not claim supported
Linux/macOS CI. TSan and additional stress workloads remain separate pending work,
not silently passing matrix legs. No performance target or zero-
allocation guarantee is introduced.
